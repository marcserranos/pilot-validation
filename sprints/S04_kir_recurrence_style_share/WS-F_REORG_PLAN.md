## 4. Risks and the test command to run after

**Risks:**
1. **Concurrent commits.** Other S04 agents are actively committing on this branch (5 commits in
   the last few hours per `git log`). A `git mv` batch executed without re-checking `git status`
   immediately before running will conflict with or silently shadow in-flight work. Re-run `git
   status` and the generator in §2 immediately before executing §6.
2. **`context/EXPERIMENTS.md`/`DECISIONS.md` append-only rule.** The biggest actual risk in this
   reorg is an agent "helpfully" running a blanket `sed` across the whole repo and rewriting
   historical entries in these two files to point at the new paths — that violates the project's
   own durability rules (§3, Category A) and destroys the audit trail's fidelity to what was true
   at the time. The shell script in §6 deliberately excludes `context/EXPERIMENTS.md` and
   `context/DECISIONS.md` from its sed targets for this reason.
3. **The 5 VM-critical files (§3.1).** Moving any of them breaks the production pipeline the next
   time the VM repo is updated from this branch, in ways that range from a loud `FileNotFoundError`
   (`run_immuannot_person.py`) to a **silent** degradation (`monitoring/` — orchestrator just stops
   heartbeating, no crash) to a 404 on a fresh VM bootstrap that won't be noticed until someone
   tries to provision a new machine (`bootstrap_vm.sh`/`setup_immuannot.sh`). Recommend treating
   §3.1's "do not move" as a hard constraint, not a suggestion to revisit later.
4. **`outputs/plots/` is a directory `git mv` of 11 files** — verify none of them are
   `.gitignore`d or otherwise absent from git's index before moving (a plain `git mv outputs/plots
   scripts/legacy/experiments_outputs/plots` will fail loudly if so, which is the safe failure
   mode — just don't paper over it with `mkdir -p` + `mv` + `git add`, which would silently lose
   history for any file git mv would have failed on).
5. **Disclosure.** None of the moved files contain participant-level data (confirmed: `outputs/`
   holds only aggregate CSVs — `allele_freq_by_ancestry.csv` and `allele_tree_data.csv` are
   frequency/tree summaries, not genotypes; the loose scripts are code, not data). No new
   disclosure exposure from this move.
