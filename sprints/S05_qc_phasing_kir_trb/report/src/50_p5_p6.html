Part 5Novel HLA alleles: what survives

Question. The earlier figures counted thousands of "novel" HLA alleles, meaning sequences not in the allele database. Before any of them becomes a headline, three questions need answers:

  1. Do they recur in unrelated people? A one-off is more likely an error.
  2. Do they avoid the known HiFi error class, a 1-base insertion or deletion in a run of one repeated base (a homopolymer, background)?
  3. Do the person's own reads carry them?

Script 50d asked the first two. Script 64 re-matched every key against IPD-IMGT/HLA 3.65.0 (July 2026, 10 releases newer than the 3.55.0 the caller used) and tested up to 5 carriers per key against the HiFi reads.

From which file, by what process (50d and 64)
Data in
Table 1 rows flagged protein-novel (the protein differs from every known one) or synonymous-novel (same protein, new DNA). The cds_mut string records how the called coding sequence differs from Immuannot's nearest known allele. For 64 there are also the person's assembly (<hap>.trimmed.fa), Immuannot's GTF and its cds.fa.gz record, the IPD 3.65.0 FASTA and allele history, and the HiFi BAM.
Process
  1. Key = (gene, cds_mut): one distinct novel sequence. The funnel counts keys, not people.
  2. Filters in order: ≥ 2 unrelated carriers; not homopolymer-indel-only; no template warning; seen on ≥ 2 platforms; in ≥ 2 ancestries (64 only); ≥ 20 clean carriers.
  3. 64 re-match: rebuild the CDS from the GTF exon rows on the contig and compare it with the cds.fa.gz record. If they disagree, the call is skipped and counted (the "CDS disagree" class). Then look for an exact match in 3.65.0: "now known" means the allele was named after 3.55.0.
  4. 64 read test: build two versions of the person's local haplotype, the called one (Wc) and the same one with the novel differences reverted to the nearest known allele (Tn). Align each spanning HiFi read to both. A read "supports" if it fits Wc better and "contradicts" if it fits Tn better. A call is supported with ≥ 3 reads assigned to that haplotype and ≥ 70% support, and contradicted at ≤ 15%. A key's reads are also pooled across its tested carriers.
Trade-offs
At most 5 carriers per key keeps the run small (4,616 calls) but means a key's verdict rests on few people. The reads are the same HiFi reads the assembly was built from, so read support is consistency, not independent proof. Short reads (a different chemistry) would be the independent test; they were not run.
Unit
Keys (distinct sequences) in the funnels; calls (one gene in one person) in the outcome figure; reads in the homopolymer figure.
Output
50_qc_foundation/protein_novel_waterfall.tsv; 64_novel_allele_validation/tables/ (funnel_with_evidence.tsv, failures_summary.tsv, hp_runlength_by_gene.tsv)
Significance

The axis here is distinct sequences surviving each test. Starting from thousands of classical "new proteins", the evidence supports a handful: 2 unnamed with clean read support and 2 since confirmed by IPD. Everything else is either a homopolymer indel the reads cannot settle, a mismatch between the caller's two outputs, or undecided at this depth.

For the paper, protein-novel counts belong in a resource table, not a headline. The new QC finding is the 345 record-vs-exon disagreements. It applies to anyone using Immuannot's CDS output, and is worth a methods note once the source is pinned down.

  • The homopolymer read figure is now marked as confounded. The code was fixed (hp_* now counts only reads assigned to the haplotype), and a rerun is planned.
  • "The frameshift is in the record, not the genome" became "source undetermined".
  • The 50d vs 64 funnel difference is now stated, not hidden.
  • Exact call counts in the outcome figure were rounded so a masked count cannot be recovered by subtraction.

Part 6MHC haplotype biology

The DQ G1/G2 pairing rule survives an ascertainment check

DQ molecules are built from one DQA1 and one DQB1 chain. Alleles fall into two groups (G1 and G2, background), and a G1 alpha chain does not pair well with a G2 beta chain. Script 37 found 0 cross-group DQA1~DQB1 haplotypes among 17,255 physically phased ones. A sceptic could argue that cross-group haplotypes exist but break contigs more often, so they are under-counted. Script 50e tested this.

From which file, by what process (50e)
Data in
Table 1 DQA1 and DQB1 calls, both haplotypes of every HLA-called person, with contig names and positions.
Process
For each haplotype label (hap1 or hap2), take the DQA1 and DQB1 calls, classify each allele as G1 or G2, and record whether the two genes sit on the same contig. If they do not, the pairing of a DQA1 with a DQB1 under one label is only as good as the assembler's labelling across a break: effectively random. The split rate is compared between within-group and cross-group pairs, and the observed cross-group share among split haplotypes is compared with the share expected if labels were random.
Trade-offs
Haplotypes, not people, so relatives add near-duplicates; that does not affect a structural question. The ≥ 100 kb spacing check was a VM inspection whose script is not committed.
Unit
Haplotypes (~22,000 with both genes called).
Output
50_qc_foundation/dq_ascertainment.tsv

An atlas of combinations that never occur

From which file, by what process (52)
Data in
Table 1, one-contig gene pairs only (both genes on the same contig of the same haplotype), at field 1 (allele lineage, e.g. DQA1*01).
Process
  1. For each gene pair, count each lineage × lineage combination.
  2. Expected count under independence: E = (rows total × column total) ÷ grand total.
  3. If a combination is truly allowed, seeing 0 has probability e−E. Call it "absent" if e−E passes a Bonferroni-corrected threshold and it is absent pooled and in ≥ 2 ancestries, each with ≥ 200 haplotypes.
Trade-offs
Independence is a null nobody believes for MHC genes, which have strong LD. So "absent" means "rarer than chance allows", not "impossible". Biology is a judgement on top.
Unit
Haplotypes.
Output
52_mhc_haplotype_atlas/absent_cells_field1.tsv, absent_pair_summary_field1.tsv

Why AMR shows more HLA alleles than AFR

Phased class II units for Cole's fine-mapping (62)

What the file contains, and how each row is made
Data in
Table 1 (DQA1, DQB1, DRB1 calls with contigs and positions), the unrelated list, 59's exclusion list (0 people), and the Part 2 trio rule.
Process
One row per person × haplotype × unit (DQA1~DQB1 and DRB1~DQA1~DQB1). Each row has the full and 2-field alleles and an evidence level: physical (all genes on one contig; trio-validated pair types), physical_flagged, split_contigs, or incomplete (a gene missing). It also has the DQ G1/G2 class, structural flags (anomalous_spacing ≥ 100 kb, anomalous_multicopy), a coverage flag (all pass) and an unrelated flag.
Trade-offs
The physical level inherits the uncalibrated k-mer origin error from Part 2. Relatives are kept (flagged), because fine-mapping models them, so the percentages below include related haplotypes.
Unit
Haplotype units (48,906 rows in total).
