Wrap-upLong jobs: plans and costs (nothing here was run)

How this report was checked: three independent reviewers (methods, numbers, readability) checked every claim against the scripts and committed tables, and their corrections are built into the text.

This sprint ran no job longer than a day. Below is every job that would, or that is short but waits for the VM, with what it answers, how long it takes and what it costs. Costs use the current VM's rate ($0.37/h for 4 vCPU and 32 GB). Bigger machines are scaled from GCP list prices, so confirm them in the Workbench resize dialog. Each long job is resumable and can be cut into batches of a day or less, so none needs a multi-day unattended run.

1 · Re-call the 991 Sequel II people (63)

Answers: HLA and KIR for the missing quarter of AFR participants. It is the largest remaining bias in every AFR number. Measured: the smoke test (13 Oct) passed at about 21 min per person on one 4-thread worker (19–23 min). For 991 people that is about 350 h of compute. Peak memory is not measured yet, so the number of workers a bigger machine can hold is a range: the low end assumes memory limits it, the high end that CPU does.

If CPU is the limit, the cost is the same on every machine (~$130) and only the calendar time changes, from about 2 weeks to 1–2 days. If memory is the limit, a bigger machine costs up to twice as much. After the calls, the merge and the reruns of 01 → 50/61/62/65 take a few hours. Recommendation: the smoke test has passed; run the 20-person Revio comparison next (about 7 h, ~$3), recording peak memory. If it agrees with production, resize to n2-highmem-80 and run 1–2 one-day batches.
