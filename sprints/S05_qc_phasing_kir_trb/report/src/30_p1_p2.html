Part 1The cohort, counted exactly

Question. How many people are in each analysis, by ancestry and platform, under each exclusion rule the repo uses? Until now every script picked its own rules, so the numbers did not line up. Script 50a builds one waterfall of exclusions, so a single list can be agreed.

From which file, by what process, counted how
Data in
cohort_membership.tsv (one row per long-read participant: platform, predicted ancestry, the six ancestry probabilities). Table 1 (hla_calls_rich.tsv) to see who has HLA calls. The relatedness pair list (kinship per related pair).
Process
  1. Start from all 13,252 cohort rows.
  2. Keep people with HLA calls.
  3. Build the unrelated set: break pairs with kinship ≥ 0.0442 by removing the most-connected person (background).
  4. Apply three purity thresholds, p ≥ 0.90, 0.95 and 0.98, where p is the probability of the assigned ancestry.
  5. Count each step overall, by ancestry and by platform.
Trade-offs
The purity thresholds were not chosen here: they are the three already used in older scripts, shown side by side so one can be picked. Greedy removal keeps more people than an optimal solution would lose, and it is deterministic.
Unit
People. Each bar shows people remaining after that step.
Output

Per-ancestry purity steps are shown as rounded percentages, not counts. Some steps remove fewer than 20 people in one ancestry, and exact counts would reveal that number by subtraction.

Two denominators you will meet. HLA analyses use 11,856 unrelated people, built from the 12,233 HLA-called people. KIR analyses (61) use 11,882 unrelated people, built from the 12,261 KIR-called people. The KIR set is slightly larger because a few people have KIR calls without HLA calls, and greedy removal depends on who is in the starting set. A single fixed unrelated list for every analysis is a cleanup item for the next sprint.

The All of Us relatedness file has disappeared from the v9 bucket. Unrelated sets now come from a cached copy of the same pairs, which script 11 saved. Scripts 59 and 61–65 use it through _s05_common.

SignificanceThe 991 missing Sequel II people are 24% of all AFR participants in the long-read cohort. Every AFR frequency in this report rests on 3,020 instead of ~4,000 unrelated people. Their 95% intervals are about 15% wider than they would be with everyone, and if Sequel II AFR people differ from Revio AFR people (another site, another period), estimates may be biased too.

Part 2Can we trust the phased haplotypes?

Question. Every haplotype claim in the project assumes that genes sitting on one contig came from one parent: the DQ rule, the atlas, Cole's fine-mapping units, the KIR haplotypes. Is that true, and for which gene pairs? Three checks answer it, each stricter than the last:

  1. how often two genes share a contig at all (50b);
  2. whether a one-contig haplotype in one relative appears intact in the other (56b);
  3. the direct truth from trios: which parent each gene came from (57, 57b).
Check 1: how often two genes share a contig (50b)
Data in
Table 1, copy-1 calls of 25 MHC genes, all 12,233 people (relatives included, which is fine for a structural question).
Process
For each haplotype and each gene pair with both genes called, ask "same contig name?". Average over haplotypes, overall and per platform. Also count how many different contigs carry MHC genes on each haplotype.
Trade-offs
This measures co-location, not correctness: a wrongly joined contig counts as "same contig". Checks 2 and 3 measure correctness.
Unit
Haplotypes, ~24,000 per gene pair. The percentage is haplotypes with both genes on one contig / haplotypes with both genes called.
Output
50_qc_foundation/same_contig_matrix.tsv, mhc_contigs_per_hap.tsv
Check 2: relatives (56b)
Data in
Table 1 plus the relatedness pairs. 569 first-degree pairs (kinship 0.177–0.354), both people HLA-called.
Process
  1. Keep pairs that share an MHC haplotype: at most 1 of 8 classical genes without a shared allele. Siblings who inherited different haplotypes share nothing and would look like errors.
  2. For each gene pair (DQA1~DQB1, DRB1~DQB1, DPA1~DPB1, B~C, A~B), take haplotypes where both relatives have the two genes on one contig.
  3. Ask whether the one-contig combination seen in relative 1 is found intact in relative 2.
Trade-offs
All of Us gives no IBD0 information, so parents and siblings cannot be told apart. Keeping only haplotype-sharing pairs removes the IBD0 siblings, but it also drops pairs where two genes are mistyped. That pushes the measured error down a little.
Unit
Haplotype tests (one gene pair in one relative pair). n = 68 (A~B) to 435 (DPA1~DPB1).
Output
56_phasing_typing_benchmark/refined_sweep.tsv
Check 3: trios, the direct truth (57, 57b)
Data in
For 179 trios: the child's hap1/hap2 contigs (assembly FASTA), the child's Table 1 rows, and both parents' HiFi reads (BAM).
Process
  1. Build k-mer databases (31-letter words, yak count) from each parent's reads over a padded window: the MHC, KIR and all of chr20 as a genome-wide control.
  2. 57, region level: run yak trioeval on the child's contig pieces to get switch and hamming error (background). This was done for 50 trios.
  3. 57b, gene level: for every child HLA gene, count paternal-only and maternal-only k-mers within ±10 kb. Assign the parent with ≥ 5 k-mers and ≥ 3× the other, otherwise "ambiguous".
  4. For each one-contig gene pair, ask whether the two genes came from different parents.
Trade-offs
k-mer databases cover only the windows, so k-mers from paralogs elsewhere are missed (this inflates error slightly). 10–31% of genes get no parent (ambiguous) and drop out. The k-mer assignment itself can be wrong, and no test here measures how often.
Unit
Gene pairs on one contig in a child: n = 81–262 per pair.
Output
57_yak_trioeval/trioeval_summary.tsv, pair_phase_truth.tsv, gene_origin_summary.tsv

Significance

This is the result the rest of the project stands on. Class II is the best-phased region in the genome sample. Any DQ or DR–DQ statement can therefore use one-contig haplotypes, and so can Cole's fine-mapping units.

Any class I haplotype claim that involves HLA-A, including the older A~B~C extended-haplotype and A–B LD tables, is wrong in about 4 of 10 haplotypes. Those results need statistical phasing before they are used.

The zero cross-group DQ count in Part 6 is itself evidence for good phasing. If phasing mixed parents at random even 5% of the time, artefactual cross-group pairs would appear by the hundreds.
