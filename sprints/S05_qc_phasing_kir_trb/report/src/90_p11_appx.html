Small-count masking: what this sprint did

Masking each count of 1–19 on its own is not enough (background). If a table shows a total and all its parts but one, the hidden part is a subtraction away. Earlier in the sprint, complementary suppression was added inside each table (_disclosure.py, used by 58, 59, 62 and 65): when exactly one cell of a sum is hidden, the next smallest is hidden too, shown as <20*.

The review found that this was still not enough, because sums also run across tables. Two examples:

  • 65's genotype counts equal sums of its allele-fraction bins;
  • 58's copy-number counts equal sums of its depth bins.

It also found such leaks in older tables (50 waterfall, DQ ascertainment, 51 allelic pairs, 53 ASE classes, 55 expression, 56 platform rows, 64 call outcomes). A cross-table masking step now re-masks the committed public tables, adding <20* where a hidden cell could be recovered. 65 and 58 now apply the cross-table sums themselves on future runs. The report text uses rounded percentages or omits values wherever a count could be recovered.

Known gaps after re-masking (checked with 66_cross_table_suppression.py --check):

  • MID's HLA-called and unrelated denominators (495 and 487) are both published in many tables, so the 8 related MID people can be worked out. Masking one table cannot hide that.
  • More generally, 65's reads_all minus reads_unrelated gives related-people counts cell by cell. Dropping reads_all from the public repo would fix it.
  • 64/tables/summary_by_stratum.tsv (counts of novel calls by gene, platform and ancestry) is not re-masked yet: too large for the solver as written.
  • Threshold sweeps (score t vs t+1, MAPQ 0 vs 20) and tables outside the review's list (56 threshold_sweep, 61, 62) are not modelled across tables yet.

Needs your decision flagged

The earlier, less-masked versions of these tables are still in the repo's git history, which is public. They can only be removed by rewriting history, and that has been ruled out so far. Options:

  1. accept the residual risk (aggregate counts, no identifiers);
  2. rewrite history on main (disruptive for Aleix's and Marc's clones);
  3. make the repo private until publication.

The rule for counts of distinct allele sequences (not people), which are shown exactly, is also still open.
