## Question

Build the smallest, most informative, documented data package for Cole (the stat-gen supervisor),
covering what he does not yet have: novel HLA calls (only common two-field alleles were shared
before), all KIR calls (never shared), ancestry probabilities/labels, unrelated-set membership,
and the DQ/DP cis-pair phasing-confidence flag he asked for on the 2026-09-22 call. See
`sprints/S04_kir_recurrence_style_share/ORCHESTRATOR_HANDOFF.md` §2 WS-E and
`sprints/ALEIX_HANDOFF_2026-09-22.md` §5.1.

## Method

- `hla_calls.tsv.gz`: reuses `24_novelty_by_field.py`'s Table 1 loader, `add_call_labels`
  (field_class/artifact_label), and `normalize_allele_name`/`n_field_name` for the two-field
  truncation. Joins 37's per-person DQ/DP phasing-confidence file when present on the VM.
- `kir_calls.tsv.gz`: reuses `41_kir_pilot.py`'s novelty-tier classifier and `44`'s contig-aware
  GTF parser (`parse_hap_gtf_full`) plus its `cds.fa.gz` join (`resolve_kir_cds_sequences`) for a
  CDS/protein sequence hash, without re-deriving either.
- `persons.tsv`: cohort membership (ancestry probabilities/label, platform) plus the same greedy
  third-degree-or-closer relatedness filter used throughout this pipeline
  (`24_novelty_by_field.greedy_unrelated`, KING kinship < 0.0442), plus per-person `hla_called`/
  `kir_called`/`exclusion_reason` flags derived from the two tables above.
- `MANIFEST.tsv`: md5 + sha256 of every deliverable, for Cole to verify the copy he receives.
- No new statistic is computed here — this script reshapes and documents already-computed calls.

## Caveats

- **Known cosmetic issue in the already-uploaded 2026-09-25 release (fixed for next time):** the
  package's own `README.md`/`SCHEMA.md` header read "release 2026-09-26" (the wall-clock date the
  script happened to run) while the bucket prefix is `release_2026-09-25` -- `date_str` was
  `time.strftime("%Y-%m-%d")` at build time, independent of the upload prefix chosen later. Not a
  disclosure or correctness issue (no data is mis-dated, only the doc header string), so the
  already-uploaded package was left as-is rather than re-uploaded for a cosmetic fix. **Fixed in
  the script** (`scripts/hla_popgen/49_cole_share_package.py`): added `--release-tag`, which now
  drives the README/SCHEMA header date; defaults to today's date if omitted, so always pass
  `--release-tag <date>` matching the upload prefix at build time for future releases.
- KIR excludes the 991 sequel2/Tier-3 people (known `run_immuannot_person.py` chr6-reference-cache
  bug, not fixed) — see `persons.tsv`'s `exclusion_reason`.
- The DQ/DP phasing-confidence column is only populated if `37_dq_g1g2_signed_ld.py
  --artifact-checks` had already been run on this VM instance and its per-person output file is
  present; otherwise the column is blank for every row and the package's own README says so.
- This is participant-level data moving between in-perimeter VM locations (VM disk -> this
  workspace's own share bucket), which is not egress, but it is not aggregate either — it must
  never be pasted into this repo, a report, or a chat message. Upload to the bucket is a separate,
  Marc-consented step; the commands are text-only in the script's own docstring, never executed by
  an agent.
